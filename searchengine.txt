## 1) Vision & Non‑Negotiables

**Vision**:  
A national search engine where any Indian (student, teacher, researcher, citizen) can type a name or query like “women scientists from Bengal” or “unsung freedom fighters from Maharashtra” and instantly get:
- The right people.
- Their correct images.
- Clear, trustworthy summaries of their contributions.
- Links to original sources.

This should feel like **Google Search**, but specialized for **Indian contributors** and optimized for **accuracy, attribution, and national memory**, with **instant response times** because all data is pre‑indexed.

**Non‑negotiables**:
- **No hallucinated facts**: Do not invent people, events, or contributions. All data must come from verifiable sources (Wikipedia, Indian Culture Portal, PIB, etc.).
- **Data sources must be 100% free and verified**:
  - Primary: **Wikipedia** (via MediaWiki API / Wikimedia Enterprise, both free).
  - Secondary: **Indian Culture Portal**, **data.gov.in**, **PIB**, **National Archives (Abhilekh‑Patal)**, **Science Reporter** – all free, government‑run sources.
  - No paid APIs, no commercial datasets.
- **Zero live external fetching at query time**:
  - All person records, images metadata, and contributions must be stored locally.
  - Search queries must hit only our **local DB + search engine**.
  - External APIs are used only in **background ingestion/enrichment jobs**.
- **Image integrity**:
  - Only use images with clear licenses (CC0, CC‑BY, CC‑BY‑SA, public domain).
  - Store and display license + attribution for every image.
- **Multilingual from day 1**:
  - English + Hindi minimum.
  - Architecture must support 22 Indian languages (via Bhashini or equivalent).
- **Search quality**:
  - Fast, relevant, typo‑tolerant search.
  - Support for filters (state, domain, era, language, gender, etc.).
- **Open & interoperable**:
  - Public APIs for other apps/portals to query “Indian contributors”.
  - Data model aligned with cultural heritage DPI (Indian Culture Portal, Gyan Bharatam).
- **Free‑for‑lifetime hosting target**:
  - Must be deployable on free tiers (Vercel + Render/Railway + Neon/Supabase) with cold‑start tolerance.
  - Document constraints and mitigation strategies.

## 2) High‑Level System Description

### 2.1 Core Capabilities

1. **Unified Person Index**
   - Entities: `Person`, `Identity` (name variants), `Contribution`, `TimelineEvent`, `Source`, `MediaAsset`, `Tag` (state, language, domain, era, gender, etc.).
   - Fields (minimum):
     - name, name_local[], birth_year, death_year, state, languages[], domains[], short_bio, contributions[], image_url, image_license, image_attribution, wikipedia_url, other_sources[], created_at, updated_at.
   - Data sources:
     - **Wikipedia** (primary): via MediaWiki API / Wikimedia Enterprise.
     - **Indian Culture Portal**, **data.gov.in**, **PIB**, **National Archives**, **Science Reporter**, etc. (as enrichment & verification).

2. **National Search Engine (Zero Live Fetch)**
   - Query types:
     - Person name search: “Rani Gaidinliu”, “Mahendra Lal Sircar”.
     - Faceted search: “women scientists from Tamil Nadu”, “freedom fighters from Odisha”, “educationists from Bengal”.
   - Features:
     - Full‑text search with typo tolerance.
     - Filters: state, domain (freedom/science/literature/education/art/etc.), era, language, gender.
     - Ranking tuned for relevance + notability + data completeness.
     - Snippet view: name, image, 1‑line contribution, source badges.
   - **Critical constraint**:
     - At query time, **no calls to Wikipedia or any external API**.
     - All results served from **local search index** (Meilisearch or Postgres FTS).

3. **Person Profile Pages**
   - Clean, Google‑style knowledge panel:
     - Portrait image (with license).
     - Short bio (2–3 paragraphs).
     - Structured contributions (3–7 bullet points).
     - Timeline of key events.
     - Sources section (Wikipedia, ICP, PIB, etc.).
     - “Share” and “Download banner” options (link to banner factory later).
   - All data loaded from **local DB**, not live Wikipedia.

4. **APIs (Public + Admin)**
   - Public read APIs:
     - `GET /api/search` (q, filters, pagination).
     - `GET /api/person/:id` (full profile).
     - `GET /api/person/:id/related` (similar contributors).
   - Admin APIs (protected):
     - CRUD for persons, contributions, sources, media.
     - Moderation for community suggestions.
   - All APIs read from **local DB/index**, no live external calls.

5. **Content Pipeline (Background Jobs Only)**
   - Automated ingestion from Wikipedia:
     - Search by categories (e.g., “Indian scientists”, “Freedom fighters from India”).
     - Extract infobox, categories, lead section, images.
     - Normalize into our schema.
   - Enrichment from government sources:
     - Cross‑reference with Indian Culture Portal, PIB lists, etc.
   - Periodic refresh jobs:
     - Scheduled jobs (e.g., nightly/weekly) to update changed Wikipedia pages.
   - Human curation layer:
     - Editorial review for quality, especially for “unsung” figures.

6. **Integrations (planned / optional)**
   - **Bhashini APIs** for translation and transliteration (used in background jobs, not at query time).
   - **Indian Culture Portal** & **Gyan Bharatam** for metadata exchange.
   - Wikimedia APIs for images and links (only in ingestion jobs).
